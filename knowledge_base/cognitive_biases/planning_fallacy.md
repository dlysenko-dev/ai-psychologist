# Ошибка планирования (Planning Fallacy)

## Определение

Ошибка планирования — систематическая недооценка времени, затрат и рисков при планировании, и одновременная переоценка выгод. Выявлена Канеманом и Тверски (1979).

Это не оптимизм — это когнитивный баг в прогнозировании. Даже осведомлённость о нём не устраняет его полностью.

## Механизм

### Inside View vs. Outside View
- **Inside view (взгляд изнутри):** "Мой проект уникален. Я учёл все факторы. Реалистичная оценка: 2 недели."
- **Outside view (взгляд снаружи):** "Похожие проекты занимают 2-3 месяца у 90% людей."

Люди по умолчанию используют inside view, который систематически оптимистичен.

### Почему inside view ошибочен
1. Фокус на план (что пойдёт ПО ПЛАНУ), игнорирование отклонений
2. Не учитывает "неизвестные неизвестные" (unknown unknowns)
3. Мотивированное рассуждение: хочется верить, что будет быстро
4. Опыт не помогает: люди повторяют ту же ошибку, даже имея данные о прошлых промахах

## Проявления у предпринимателей

### Недооценка времени до дохода
- Ожидание: "Через 2 месяца будет доход"
- Реальность: через 6-12 месяцев (если вообще будет)
- Результат: разочарование → переключение на новый проект ("этот не работает")

### Переоценка спроса
- "Мой продукт нужен миллионам" (optimism bias)
- "1% рынка — это уже $100K" (1% fallacy — захватить 1% рынка невероятно сложно)
- Не учитывается: каждый клиент требует маркетинга, поддержки, удержания

### Недооценка сложности монетизации
- Технический MVP = 20% работы
- Маркетинг + продажи + поддержка + итерации = 80% работы
- Большинство разработчиков планируют только первые 20%

### Серийная ошибка
Предприниматель с 10 проектами, скорее всего, недооценил каждый:
- Проект 1: "Запущу за месяц" → 3 месяца → бросил
- Проект 2: "На этот раз за месяц" → 3 месяца → бросил
- Проект 3: "Теперь точно за месяц"...
- Каждый раз inside view "побеждает" опыт

## Связь с другими искажениями

- **Optimism bias:** переоценка шансов на успех
- **Overconfidence:** "Я справлюсь быстрее, чем другие"
- **SOS:** если план "не сработал" за ожидаемое время → переключение (а план был нереалистичным)
- **Sunk cost:** "Я уже потратил 3 месяца (хотя планировал 1) — не могу бросить"

## Терапевтический подход

### 1. Reference Class Forecasting (Прогноз по классу аналогов)
Вместо inside view → outside view:
- "Сколько времени аналогичные проекты заняли у ДРУГИХ людей?"
- "Сколько времени твои ПРЕДЫДУЩИЕ проекты заняли на самом деле?"
- Использовать данные, а не интуицию

Практическое упражнение: составить таблицу
| Проект | Оценка | Реальность | Коэффициент |
|--------|--------|------------|-------------|
| Проект A | 2 недели | 2 месяца | x4 |
| Проект B | 1 месяц | 4 месяца | x4 |

Личный коэффициент: x4. Теперь умножай каждую оценку на 4.

### 2. Pre-mortem (Предсмертный анализ)
Техника Гэри Клейна:
- "Представь, что прошло 6 месяцев и проект НЕ приносит дохода. Что пошло не так?"
- Перечислить ВСЕ возможные причины провала
- Для каждой причины — план B

Эффект: переключает мозг из режима оптимизма в режим реализма.

### 3. Disaggregation (Разбивка на компоненты)
Вместо "запустить продукт":
1. MVP функционал — 2 недели → реально 4 недели
2. Тестирование — 3 дня → реально 1.5 недели
3. Landing page — 2 дня → реально 1 неделя
4. Маркетинг запуска — 1 неделя → реально 3 недели
5. Первые продажи — 1 неделя → реально 1-3 месяца
6. Итерации по фидбэку — 2 недели → реально 2 месяца

Сумма по частям всегда реалистичнее общей оценки.

### 4. Buffer Inflation (Буферное раздутие)
Правило: к любой оценке добавить 50-100%.
- "1 месяц" → планируй 2 месяца
- "3 месяца" → планируй 5-6 месяцев
- Лучше закончить раньше, чем разочароваться

### 5. Milestone-Based Planning (Планирование по вехам)
Вместо "запустить к 1 марта":
- Веха 1 (1 февраля): MVP работает
- Веха 2 (15 февраля): 5 бета-тестеров
- Веха 3 (1 марта): первый платящий клиент

Если веха не достигнута — пересмотреть план (а не "поднажать").

## Ключевые вопросы для терапевтической сессии

- "За какое время ты планировал завершить свой последний проект? За какое реально завершил?"
- "Если бы незнакомый человек описал тебе этот план — ты бы поверил в сроки?"
- "Что может пойти не так? Перечисли 5 вещей."
- "Какой твой личный 'коэффициент реальности'?"
- "Как бы выглядел план, если бы ты заложил на всё в 2 раза больше времени?"
