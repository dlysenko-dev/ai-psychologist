# Bikeshedding (Закон тривиальности Паркинсона)

## Определение

Bikeshedding — когнитивное искажение, при котором человек тратит непропорционально много времени на тривиальные, понятные задачи и избегает сложных, непонятных, но критически важных.

Название: Паркинсон описал комитет, который за 2 минуты утвердил проект атомного реактора (слишком сложно, чтобы обсуждать), но 45 минут спорил о навесе для велосипедов (все "эксперты").

## Близкий паттерн: Yak Shaving

Yak Shaving — выполнение бесконечной цепочки "необходимых" подготовительных задач, которые уводят от оригинальной цели.

Пример: "Не могу запустить продажи → сначала нужен сайт → сначала нужен дизайн → сначала нужен логотип → сначала нужно изучить Figma..."

## Нейронный механизм

### Принцип наименьшего сопротивления (Cal Newport)
Мозг выбирает задачу с наименьшим когнитивным сопротивлением:
- Простая техническая задача: низкое сопротивление (знакомая, предсказуемая)
- Бизнес-задача (продажи, ценообразование): высокое сопротивление (незнакомая, тревожная)

Мозг буквально оптимизирует энергозатраты, выбирая "лёгкий" путь.

### Completion bias (Склонность к завершению)
Мозг получает дофамин от ЗАВЕРШЕНИЯ задач. Маленькие задачи завершаются быстро = быстрый дофамин. Большие задачи (монетизация) завершаются нескоро = нет дофамина.

Результат: список из 50 завершённых мелких задач + 0 завершённых критических.

### Illusion of productivity (Иллюзия продуктивности)
"Я весь день работал" — правда. Но работа была на тривиальных задачах. Мозг не различает "полезную" и "бесполезную" продуктивность — усталость одинаковая.

## Проявления у предпринимателей

### Технический bikeshedding
- 3 дня на выбор цветовой схемы (пока ни одного клиента)
- Рефакторинг кода, который работает (но никто не платит)
- Оптимизация производительности на 0.1 секунды (при 0 пользователей)
- Миграция на новый фреймворк (пока нет MVP)

### Инфраструктурный yak shaving
- Настройка CI/CD (для проекта без пользователей)
- Мониторинг и алерты (нечего мониторить)
- Docker + Kubernetes (для одного сервиса)
- "Правильная" архитектура (для MVP)

### "Подготовительный" bikeshedding
- "Сначала создам идеальный рабочий стол" → организация файлов 3 часа
- "Сначала прочитаю книгу о маркетинге" → чтение 2 недели
- "Сначала сделаю визитки" → дизайн визиток 3 дня
- Ни одно из этого не приносит дохода

### Определяющий признак
**Вопрос:** "Эта задача напрямую увеличит шансы на доход?"
- "Нет, но она нужна для..." = bikeshedding
- "Да, если я отправлю это предложение клиенту" = реальная работа

## Терапевтический подход

### 1. Task Classification Matrix (Матрица классификации задач)

| | Приносит доход | Не приносит доход |
|---|---|---|
| **Нравится** | Приоритет 1 ✅ | Ловушка bikeshedding ⚠️ |
| **Не нравится** | Делай ПЕРВЫМ 🔥 | Удали из списка ❌ |

Правило: задачи в ячейке "Не нравится + Приносит доход" = ПЕРВЫЕ в дне.

### 2. "Revenue-First Morning" (Утро дохода)
Первые 60-90 минут дня — ТОЛЬКО задачи, прямо связанные с доходом:
- Написать клиенту
- Опубликовать продукт
- Провести продающий разговор
- Выставить счёт

После этого — разрешение на технические задачи.

### 3. Stop-Loss для мелких задач
Правило: если задача не связана напрямую с доходом — максимум 1 час.
- Настройка IDE: 30 минут, потом стоп
- Выбор шрифта: 15 минут, потом стоп
- Рефакторинг: 1 час, потом стоп (если нет платящих пользователей)

### 4. "Один главный результат дня" (MIT — Most Important Task)
Каждое утро определить ОДНУ задачу, которая больше всего приближает к доходу. Эта задача — первая и обязательная. Всё остальное — бонус.

### 5. Аудит времени (Time Audit)
В течение 3 дней записывать каждые 30 минут: что делаю? Это приближает к доходу?
- Обычно результат шокирует: 80% времени — bikeshedding
- Визуальное доказательство паттерна

## Ключевые вопросы для терапевтической сессии

- "Чем ты занимался вчера? Что из этого напрямую связано с доходом?"
- "Если бы у тебя был только 1 час в день — что бы ты сделал?"
- "Какую самую неприятную бизнес-задачу ты откладываешь? Почему?"
- "Заметил ли ты, что выбираешь 'интересные' задачи вместо 'важных'?"
- "Что бы произошло, если бы ты НЕ делал то, что делал вчера?"

## Источники

- Newport C. (2016) — Deep Work (Principle of Least Resistance)
- Zeigarnik B. (1927) — Zeigarnik Effect (completion bias)
- Allen D. (2001) — Getting Things Done (MIT concept)
